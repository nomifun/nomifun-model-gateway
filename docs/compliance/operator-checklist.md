# 运营方责任与上线证据

本清单分配部署与商业运营职责，不宣称某一实例已获认证、已完成审批或自动满足适用法律。
具体要求由运营方按经营地区、服务范围、模型来源和支付模式核实，并保存自己的上线证据。
NomiFun 官方不代办、代持或承担伙伴实例的商业运营。

| 工作 | 负责人 | 需保留的证据 |
| --- | --- | --- |
| 域名、站点和适用备案/许可 | 实例运营方 | 适用范围判断、备案或许可材料、域名控制与 HTTPS 证书 |
| 内容安全、模型使用条款与上游授权 | 实例运营方 | 模型供应协议、内容处置流程、投诉和升级路径 |
| 适用的实名认证/身份核验 | 实例运营方 | 适用判断、流程、数据最小化与保存规则 |
| 日志留存、安全事件与取证 | 实例运营方 | 保存期限、访问权限、删除流程、事故处理；默认不保存模型内容 |
| 支付资质、官方商户接口与财务对账 | 实例运营方 | 自己的商户资质、支付渠道约定、回调/订单对账与退款流程 |
| 服务条款、订阅、价格和取消/退款 | 实例运营方 | 向用户公示的 HTTPS 页面、价目与账单支持渠道 |
| 隐私、数据位置与子处理方 | 实例运营方 | 隐私告知、上游列表、传输目的、删除/导出与访问流程 |
| 上游 API 与商业使用边界 | 实例运营方 | 正式 API 凭据和授权范围；不借用面向个人订阅的反向代理通道 |
| 软件许可证与品牌来源 | 发行/运营方 | 锁定版本、许可证报告、NOTICE、依赖声明和必要的来源归属 |
| 安全、备份和容量 | 实例运营方 | 恢复演练、秘密管理、漏洞处置、符合实际业务的压测 |

付款后在网页上跳转“成功”不表示网关可入账；必须以经过商户、金额、币种、订单和签名校验的
官方通知/查询为准。合成测试和本地运行结果不替代真实支付商户验证。

本项目不内置发票/税务、身份核验服务或多节点高可用方案。运营方不能据此省略自己需要完成的
工作，也不能把这些能力写成已提供的产品功能。易支付等非官方聚合通道不默认内置。
