## 视觉与交互

参考同级 `portal/codevisual` 的本地组件展示，采用中性黑白灰、细边框、统一圆角、
数字排版与少量语义状态色。参考目录没有正式 LICENSE 或 Git 提交，因此没有复制其
组件实现、字体或资源，也没有引入其依赖。当前实现沿用锁定的 React、Arco、UnoCSS
与 i18next，通过原创 CSS tokens 和可复用页面组件实现。

- 登录/注册、用户工作台和管理员工作台共享视觉系统，支持浅色和深色主题。
- 六个用户页面和十一个管理页面分别组织导航；管理导航按模型服务、商业、运营分组。
- 页面 hash 支持刷新定位与浏览器返回；Ctrl/Cmd+K 搜索跳转；跳过导航保留当前页面。
- 业务弹窗可见时快捷搜索不打开，避免丢弃未保存字段或一次性密钥。
- 概览包含真实余额、套餐、额度、三步接入指引和最近调用；未披露额度不显示为无限或零。
- 模型卡片支持搜索、厂商/任务筛选和详情；列表支持状态筛选、精确整数排序及空状态恢复。
- 编辑器关联 label/id，逐字段校验并聚焦首错；必填字段始终可见，可选限制位于高级设置。
- 手机使用导航抽屉、单列卡片和可滚动表格；动画和验证滚动遵守 reduced-motion。

额外修正了实际操作中发现的契约问题：模型状态表单改为后端要求的
`available/degraded/unavailable`；支付宝补上服务端要求的 `merchant_id`；移除模型
编辑器里无效的 `included_in_plan` 开关，该值由服务端根据当前账户计算。
开发代理默认指向网关的 8789 端口，并保留浏览器 Host/Origin 对，不放宽服务端同源保护。

## 实际浏览器证据

使用真实 Go 服务和独立临时 SQLite 数据库，所有账户、模型、金额和密钥均为合成验收数据。
前端未添加 mock fallback。开发代理在 5185，初始验收网关在 19194；最终单二进制预览在
`http://127.0.0.1:19195/console/`，不依赖 Vite 服务。临时运行文件位于系统 Temp 的
`nmg-ui-acceptance-*` 目录，没有写入仓库。

1. 巡检全部 17 个页面，确认正确标题、API 数据/明确空状态和可见操作，没有 API 错误提示。
2. 实际创建密钥，提交空名称会显示字段错误并聚焦名称；展开高级限制后提交
   `9007199254740993` 配额，列表保持该精确值。创建结果只在一次性弹窗展示明文。
3. 实际创建模型，默认可用状态通过服务端校验并显示在管理列表和用户目录。
4. 实际通过管理员表单调整测试钱包，真实响应与账户页显示 `USD 129.00`。
5. 搜索无匹配后可清除筛选；搜索跳转、返回、刷新定位和跳过导航均保持预期页面。
6. 模型编辑弹窗内按 Ctrl+K，确认业务弹窗仍为一个，没有打开快捷搜索或丢失表单。
7. 验证中英文、浅深色；修正深色主按钮文字后，浅按钮底色配深文字。
8. 检查 390×844 手机与 880×600 紧凑桌面布局；手机登录、目录、抽屉和编辑弹窗可用，
   页面没有横向溢出。临时视口已恢复。
9. 最终 Go 内嵌构建登录与账户/目录/支付配置页面通过实际浏览器验收。
