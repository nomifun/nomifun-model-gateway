## 独立进程 HTTP 验收

从项目根目录启动实际 Mock 进程：

```powershell
go run ./cmd/mock-gateway --listen 127.0.0.1:18788 --stream-delay 1ms
```

另一个终端通过 HTTP 运行 CLI：

```powershell
$env:NMG_BASE_URL = 'http://127.0.0.1:18788'
$env:NMG_API_KEY = 'nmg_mock_development'
$env:NMG_FIXTURE_FILE = 'testdata/conformance.json'
go run ./cmd/conformance
```

最终输出：

```text
Results: 226 PASS, 0 FAIL, 0 SKIP
```

覆盖鉴权组合和冲突、匿名 meta、目录/账户契约、目录权限隔离、四类原生 JSON/SSE、工具与签名、图片生成和 multipart 编辑、embeddings、rerank、Responses 续接与跨 key 隔离、完整无状态加密 reasoning/工具历史重放，以及五类业务错误在 OpenAI、Anthropic、Gemini 下的结构。全部 key、签名、用量和上游通道均为合成数据。测试结束后停止该 Mock，确认 18788 端口不再监听。CLI 的默认开发端口仍为 8788；18788 仅用于本次验收。

## 关键协议决定与验证边界

- 同一个实例 key 支持三个鉴权头。Gemini 的 `?key=` 仅作为两个原生入口的入站兼容例外；桌面、示例、deep link、购买链接及日志遵守无凭据 URL 规则。
- Gemini 保留数字型 `error.code`，业务字符串码使用 `google.rpc.ErrorInfo.metadata.nomifun_code`；OpenAI 与 Anthropic 使用扩展 `error.code`。原生错误和未知字段保留。
- 任务必须明确声明识别得到的首选端点，目录格式错误时整次导入失败；首选 Anthropic 必须有正整数输出上限。
- schema 检查读取实际 OpenAPI，编译全部本地 JSON Schema，并验证 Mock 返回值、23 类非法目录样本、int64 边界和原生错误扩展；未宣称运行完整官方 OAS 文档元 schema 验证。开放原生正文 schema 不替代上游完整 API 定义。
- Mock 亲和记录存在于内存中；重启后 Responses 未知 parent 失败，Anthropic 客户端应使用新的会话 ID。生产持久化、丢失绑定后的失败关闭和真实上游保真属于 M1。
- M0 没有真实上游、数据库、账本、支付、控制台、Docker 交付或桌面 Provider。未使用附件中的真实模型 key，也没有复制外部网关实现或读取受禁项目源码。
- M0 无阻塞项。客户端中断后的生产计费策略仍需在 M1 明确；实际上游 thinking、工具、usage 对账与存储续接必须与 Mock 验收分开记录。后续里程碑尚未开始。
