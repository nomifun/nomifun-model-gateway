# NomiFun Model Gateway Protocol v1

协议版本：`1.0`。本文件与仓库根目录的 [openapi.yaml](../../openapi.yaml) 共同定义公共契约；控制面 JSON 的字段、必填项和数值范围以 OpenAPI 3.1 schema 为准，跨字段约束及原生直通行为也必须遵守本文。M0 冻结此契约并提供合成 Mock 和一致性检查；生产转发、计费、支付和桌面接入分别属于后续里程碑。

NomiFun 官方只提供开源软件、开放协议和可选的桌面 provider，不运营网关实例、不出售 API，也不运营任何付费服务。网关由社区伙伴独立运营。`operator` 描述当前实例的实际运营方；示例域名、Mock 运营方和合成模型不代表官方托管服务。

## 1. 地址、版本与兼容性

客户端在运行时填写网关的 **API 根地址**，不得内置某个商业实例。以下路径均相对于根地址；例如 `https://gateway.example` 的元数据路径是 `https://gateway.example/nomifun/v1/meta`。生产地址使用 HTTPS；本机 Mock 可使用 HTTP。运营方、控制台、购买、条款和隐私链接只能是绝对 HTTPS URL，不能含凭据。购买链接交给系统浏览器打开，不把 API key 拼进去。

`contract_version` 必须为字符串 `"1.0"`，不是数字。v1 的所有已定义字段均必填；可空字段以显式 `null` 表示，不能省略。列表即使为空也返回 `[]`，不能返回 `null`。接收方接受并忽略控制面未知的附加字段；这不意味着可以猜测未知的任务、端点、首选协议或版本。v1 不变更已有字段的类型或含义，破坏性变更使用新版本。原生请求、响应和事件中的未知字段必须保留，不能因为控制面 schema 而过滤。

所有整数使用有符号 `int64`：范围 `-9223372036854775808` 至 `9223372036854775807`。金额采用货币的最小单位，例如 USD 的 cent、CNY 的分、JPY 的日元；不使用浮点金额。JSON 消费者必须以能精确表示 int64 的方式读取这些数值，不能先转为 JavaScript `Number` 再进行账务计算。

## 2. 鉴权和凭据边界

`GET /nomifun/v1/meta` 匿名访问。其余控制面与原生端点使用同一个实例 API key，并接受下列任意一种请求头：

```http
Authorization: Bearer <API_KEY>
```

```http
x-api-key: <API_KEY>
```

```http
x-goog-api-key: <API_KEY>
```

客户端通常只发送一个鉴权头。多个来源给出相同的有效 key 时可以接受；给出不同凭据、空凭据、格式错误的 Bearer，或同一个来源出现多个值时，服务必须拒绝为 HTTP 401 `invalid_api_key`，不能选择其中一个覆盖其他凭据。Bearer scheme 不区分大小写，后面必须恰好一个空格，再跟一个不含空白或逗号的可打印 key。两个 key 请求头也必须只有一个非空、不含空白或逗号的可打印值。鉴权头名称不区分大小写。网关验证的是实例 key，转发时使用运营方配置的上游凭据，不能把用户实例 key 当成上游 key。

为了兼容 Gemini 原生客户端，**仅**以下两个原生 Gemini 路径接受查询参数 `key`：`/v1beta/models/{model}:generateContent` 和 `/v1beta/models/{model}:streamGenerateContent`。这是 v1 唯一的入站 URL 凭据例外；其他路径出现 `key` 时拒绝请求。桌面端、文档示例、deep link 和购买链接始终使用请求头或完全不携带凭据，不生成带 key 的 URL。部署入口、反向代理和网关均不得记录含查询 key 的 URL；访问日志应记录路径模板而不是原始 URL，并对鉴权头、查询 key 和上游密钥脱敏。网关向上游的请求也优先使用请求头，不把密钥添加到 URL。

携带凭据的 HTTP 请求不跟随重定向。客户端和网关都不得在 3xx 后自动将凭据转发到新位置，即使新位置看起来属于同一服务；应验证并显式重新配置根地址。

每个响应，包括错误和流式响应，必须包含 `x-request-id` 和 `Cache-Control: no-store`。`x-request-id` 是非空、不含凭据的实例请求标识，用于诊断和后续账本幂等；不能记录请求或响应正文作为诊断默认值。HTTP 429 还必须返回合法的 `Retry-After`，Mock 使用秒数形式。

## 3. 端点能力和桌面任务

控制面核心端点和兼容模型列表必须存在：

| 方法 | 路径 | 鉴权 | 用途 |
| --- | --- | --- | --- |
| GET | `/nomifun/v1/meta` | 无 | 实例版本、运营方、能力 |
| GET | `/nomifun/v1/catalog` | 是 | 当前 key 有权使用的完整目录 |
| GET | `/nomifun/v1/account` | 是 | 当前 key 的账户快照 |
| GET | `/v1/models` | 是 | OpenAI 兼容模型列表，仅限当前 key 可见模型 |

`capabilities` 使用端点族词表；它不是任务列表。实例可以只声明所实现的端点族，目录不能引用未声明的端点族。已声明的端点族必须实现相应路径；模型只声明实际支持的任务。未声明的原生端点可返回 HTTP 501 `unsupported_endpoint`。M0 的 bundled Mock 实现全部 v1 端点族。音频端点词 `audio-speech`、`audio-transcription` 留给后续版本，不能出现在 v1 `capabilities` 或目录中。

| 端点族 | 原生路径 | 对应桌面任务 | 桌面协议 / 连接角色 |
| --- | --- | --- | --- |
| `openai` | POST `/v1/chat/completions` | `chat` | `openai.chat_text` / `default` |
| `openai-response` | POST `/v1/responses` | `chat` | `openai.responses` / `default` |
| `anthropic` | POST `/v1/messages` | `chat` | `anthropic.messages` / `anthropic` |
| `gemini` | POST `/v1beta/models/{model}:generateContent`、POST `/v1beta/models/{model}:streamGenerateContent` | `chat` | `gemini.generate_text` / `gemini` |
| `image-generation` | POST `/v1/images/generations`、POST `/v1/images/edits` | `image_generation`、`image_edit` | `openai.images` / `default` |
| `embeddings` | POST `/v1/embeddings` | `embedding` | `openai.embeddings` / `default` |
| `jina-rerank` | POST `/v1/rerank` | `rerank` | `generic.rerank` / `default` |

图片端点按模型声明的任务开放：仅支持生成的模型不需要声称支持编辑。`image-generation` 同一个端点族分别承载生成与编辑任务，客户端不能把这两个任务名合并为一个。`/v1/messages/count_tokens` 为可选 Anthropic 原生端点；支持时在 `optional_endpoints` 中精确声明这个路径，没有声明时客户端不依赖它。Gemini 流式请求可显式使用 `alt=sse`，它不是凭据；网关入口省略 `alt` 时也默认使用 SSE。显式提供其他 `alt` 值则返回 HTTP 400 `invalid_request_error`。

默认连接使用 Bearer 和根地址加 `/v1`；Anthropic 连接使用 `x-api-key` 和根地址；Gemini 连接使用 `x-goog-api-key` 和根地址。桌面端从目录显式保存每项任务的协议和连接角色，运行时不提供静态协议猜测或跨协议兜底。M0 不修改桌面端。

## 4. 控制面数据

### 4.1 Meta

```json
{
  "contract_version": "1.0",
  "operator": {
    "name": "Example Community Operator (Mock)",
    "homepage_url": "https://operator.example/",
    "console_url": "https://operator.example/console",
    "purchase_url": "https://operator.example/purchase",
    "terms_url": "https://operator.example/terms",
    "privacy_url": "https://operator.example/privacy"
  },
  "capabilities": ["openai", "openai-response", "anthropic", "gemini", "image-generation", "embeddings", "jina-rerank"],
  "optional_endpoints": ["/v1/messages/count_tokens"]
}
```

`operator.name` 必须非空。五个链接字段都必填，未提供的链接为 `null`。`capabilities` 与 `optional_endpoints` 是不重复的列表；无可选端点时使用 `[]`。

### 4.2 Catalog

```json
{
  "contract_version": "1.0",
  "models": [{
    "id": "mock-gpt",
    "display_name": "mock-gpt",
    "vendor": "openai",
    "tasks": ["chat"],
    "task_endpoints": {
      "chat": {
        "endpoints": ["openai-response", "openai"],
        "preferred_endpoint": "openai-response"
      }
    },
    "context_window": 128000,
    "max_output_tokens": 8192,
    "input_modalities": ["text", "image"],
    "traits": ["vision_input"],
    "pricing": [{"task": "chat", "meter": "requests", "unit_size": 1, "amount": 0, "currency": "USD"}],
    "included_in_plan": true,
    "status": "available"
  }]
}
```

`models` 只返回当前 key 可使用的模型，`id` 在实例内稳定且唯一。`/v1/models` 的可见集合必须与目录一致，但它不是这个丰富目录的替代品。

每个模型包含全部下列字段：

| 字段 | 类型 / 含义 |
| --- | --- |
| `id`、`display_name`、`vendor` | 非空字符串 |
| `tasks` | 不重复的任务列表；v1 仅 `chat`、`image_generation`、`image_edit`、`embedding`、`rerank` |
| `task_endpoints` | 任务名到 `{endpoints, preferred_endpoint}` 的映射，与 `tasks` 完全一致 |
| `context_window` | 正 int64 或 `null`；未知或不适用时为 `null` |
| `max_output_tokens` | 正 int64 或 `null`；首选 `anthropic` 时必须是正 int64 |
| `input_modalities` | 非空模态名的列表，如 `text`、`image`、`audio`、`video` |
| `traits` | 特征字符串列表；未知特征不等于新的协议选择规则 |
| `pricing` | 本模型任务的价格条目列表；空列表表示未公布价格 |
| `included_in_plan` | 当前套餐是否包含该模型；不替代 key 权限过滤 |
| `status` | `available`、`degraded` 或 `unavailable`；可见但暂时不可用的模型不自动删除 |

`endpoints` 非空且不重复。`preferred_endpoint` 必须存在、是 v1 已知端点、属于该任务的 `endpoints`，并满足上述任务映射。任何任务缺失首选端点、首选值未知或不在可选列表中，**整次目录导入失败**，不猜测、不悄悄跳过模型，也不部分保存。首选 `anthropic` 且 `max_output_tokens` 缺失、为 `null`、非整数或非正数同样失败。目录中的格式错误与模型是否暂时不可用是不同问题。

一个价格条目为 `{task, meter, unit_size, amount, currency}`：`task` 必须是本模型的一项任务；`meter` 是明确的计量维度；`unit_size` 是正 int64；`amount` 是非负 int64，表示每 `unit_size` 个该维度的最小货币单位价格；`currency` 是大写三字母货币码。缺失某个 meter 的价格表示未定价，**不表示免费**；`amount: 0` 才明确表示免费。不能重复发布同一任务、meter、currency 的价格条目。

建议 meter 词包括 `requests`、`input_tokens`、`output_tokens`、`cached_input_tokens`、`cache_creation_input_tokens`、`cache_read_input_tokens`、`reasoning_tokens`、`images`。meter 可扩展，但部署必须说明计量集合。推理 token 和缓存 token 在不同原生协议中可能是总量的子集；不能把已包含在 `output_tokens` 中的推理量再次按普通输出价计费。若使用独立推理价格，普通输出维度必须扣除已单独计费的推理量；缓存维度也必须避免与输入维度重叠。控制面报价不把所有上游 usage 强行变成一个统一格式。

### 4.3 Account

```json
{
  "contract_version": "1.0",
  "plan": {
    "name": "Mock Development",
    "period_start": "2026-10-01T00:00:00Z",
    "period_end": "2099-11-01T00:00:00Z",
    "quota": {"unit": "tokens", "total": 1000000, "used": 0}
  },
  "balance": {"amount": 12345, "currency": "USD"},
  "key": {"name": "Mock development key", "expires_at": null, "quota_unit": "tokens", "remaining_quota": 1000000},
  "rate_limits": {"requests_per_minute": 60, "tokens_per_minute": 100000, "concurrent_requests": 4}
}
```

`plan` 必填，可为 `null`，表示没有可展示的当前套餐信息。非空套餐必须包含 `name`、`period_start`、`period_end` 和 `quota`；周期字段可以为 `null`，表示没有该边界信息。所有非空时间是 UTC RFC 3339 字符串，使用 `Z` 后缀；非空结束时间不得早于开始时间。

`quota.total`、`key.remaining_quota` 与三个 `rate_limits` 字段均必填且可空；非空值为非负 int64。这里的 `null` 统一表示 **未知、未披露或不适用的数值**，客户端不得显示为“无限”、0 或推算剩余额度。v1 不定义数值型的无限配额标记。`0` 是明确的零额度或零允许量；正数是明确的额度。`quota.used` 是非负 int64，即使 `total` 未知也可以展示已用量；单位 `unit` / `quota_unit` 必须明确且非空。

`key.expires_at: null` 单独定义为此 key 无到期时间；非空为 UTC RFC 3339。账户永远不返回 key 的明文或哈希。`balance.amount` 是有符号 int64，允许明确展示负余额；价格为非负数的规则不适用于余额。`balance.currency` 使用大写三字母货币码。账户只是查询时的快照，不能替代服务端的实时鉴权、限额和计费检查。

## 5. 原生请求、流式响应和 usage

v1 使用**同协议原生直通**。请求和成功响应保持各自原生协议的字段、结构和语义，不进行 Chat、Responses、Anthropic、Gemini 之间的转换。OpenAPI 中的推理正文是开放的原生对象，而不是上游 API 的完整字段验证器；真正的必填字段和模型能力由原生协议决定。图片编辑保留原生 multipart 文件上传语义。

网关入口的 `anthropic-version` 为可选请求头；显式提供时原样转发。不提供时，M1 网关使用运营方配置的原生版本默认值并声明该策略，不能按客户端模型猜测版本，也不做版本转换。M0 可以接受省略该头的合成请求，不证明真实上游会接受没有版本头的请求。

流式端点返回 `text/event-stream`，保留原生事件名、顺序、数据、终止标识和未知字段。尤其不能丢失 thinking 内容/签名、加密 reasoning、工具调用增量、缓存字段或尚未认识的事件。旁路解析 usage 不得重写客户端收到的原生事件，不得把 Anthropic 或 Gemini 流转换成 OpenAI 流。

| 协议 | usage 来源与计量注意事项 |
| --- | --- |
| OpenAI Chat | 请求必要时补充 `stream_options.include_usage: true`；保留其他 stream_options，读取 usage chunk；最终 usage chunk 的 choices 可以为空 |
| OpenAI Responses | 读取 `response.completed` 的 response.usage；保留 reasoning / encrypted content；区分 output 总量和其中的 reasoning 子量 |
| Anthropic | `message_delta` 的输出 usage 是累计值，不能累加各个 delta；完整输入量由未缓存 input_tokens + cache_read_input_tokens + cache_creation_input_tokens 组成，保留全部原生缓存维度 |
| Gemini | 读取 usageMetadata；promptTokenCount 已包含 cachedContentTokenCount，totalTokenCount 已包含 thoughtsTokenCount，不能重复相加；保留每个原生维度 |

可以补充取得 usage 所必需的原生选项，但不能改变显式请求字段的含义，不能过滤未知请求字段。是否取得完整 usage、如何使用原生计量价格以及核对实际上游数据，是 M1 的生产验证义务；M0 的合成数字不证明真实计量准确。

连接超时与流式空闲超时必须有明确配置。流式请求**不设置总时长超时**；每次收到上游字节重置空闲计时。客户端取消或断开时同步取消上游请求，关闭流并释放相关资源。失败切换仅允许发生在向客户端发送第一个字节之前；发送任何响应字节后不得重新发起另一个上游请求拼接流。即使还没有字节，有亲和约束的请求也不能切换到另一个上游账号。

已发送响应头或流数据后发生错误，保留原生协议允许的错误事件和终止行为；不能向一个已经开始的 SSE 流追加伪装为完整 JSON 的另一种错误结构。客户端区分终止成功和异常断流。

**中断计费策略尚未在 M0 冻结。** M1 部署在提供收费服务前必须声明客户端断开、上游空闲超时、仅有部分 usage 或缺失最终 usage 时如何预扣、结算或释放，以及估算/上游实付的处理方式。默认不记录请求/响应正文。M0 无钱包、预扣、账本或收费行为，不能把 Mock 的完成次数当作生产账单证据。

## 6. 有状态请求的亲和路由

### 6.1 Responses

必须完整保留 `store`、`previous_response_id` 和 `include: ["reasoning.encrypted_content"]`。网关以**已验证的当前 key 身份 + response_id** 记录返回响应所使用的上游账号；将来对该 response_id 的续接必须使用同一账号。不能仅按模型、公开 response_id 或缓存概率选账号，也不能跨 key 读取绑定。

`previous_response_id` 未知、过期、跨 key、绑定丢失或指向不再可用的账号时，返回 HTTP 400 `invalid_previous_response_id`，不尝试新账号，不导入其他 key 的状态。跨 key 和未知 ID 的外部错误一致，避免泄露绑定是否存在。`store: false`、加密 reasoning 或客户端显式发送历史内容不能被误当作访问另一 key 状态的权限。绑定保存期限不得短于所提供的上游续接有效期；部署须声明期限，期限终结后失败关闭。

### 6.2 Anthropic prompt cache

使用可选头 `X-NomiFun-Session-ID: <opaque-session-id>` 提供会话身份。若提供，则以当前 key 身份和该 ID 固定上游账号；同一会话的有效期内不因负载、冷却或故障切换账号。这个头由网关消费，不当作上游 key。

v1 会话采用 **24 小时空闲期限**；成功活动刷新空闲期限。绑定过期或丢失时必须失败关闭，不能把已存在会话 ID 静默绑定到另一账号。客户端显式生成新的不重复会话 ID 才能开始新会话。生产存储必须能够区分首次出现的新 ID 和失效/丢失的旧绑定；多节点时共享绑定和失效状态，不能把单节点内存丢失伪装为新的会话。未发送该头时不保证 prompt cache 亲和，客户端仍然保留全部原生缓存字段。缓存命中本身由原生上游决定，不由网关凭空保证。

M0 的上游账号和缓存行为都是合成夹具，验证身份隔离、稳定路由、空闲失效拒绝及协议字段。Mock 的绑定与失效标记只在进程内存中：Mock 重启后客户端必须显式生成新 session ID，不能以它验证生产恢复安全。真实上游存储期限、缓存命中、多节点共享和持久化恢复不属于 M0 已验收能力，生产部署必须补齐上述失败关闭语义。

## 7. 错误和用户操作

网关产生的错误遵循被调用协议的原生 envelope；上游返回的未知原生错误保留其原生结构与字段，不强制套用网关业务字段。控制面使用 OpenAI 风格 envelope。所有错误包含请求响应头 `x-request-id` 和 `Cache-Control: no-store`，业务错误中 `purchase_url` 为运营方的绝对 HTTPS 购买链接或 `null`；即使错误可重试，也不能把该链接当作 API 路由。

| 业务码 | 典型 HTTP 状态 | 含义 / 客户端动作 |
| --- | --- | --- |
| `insufficient_balance` | 402 | 余额不足，显示充值入口，不盲目重试 |
| `subscription_expired` | 403 | 套餐过期，显示续费入口 |
| `model_not_in_plan` | 403 | 当前套餐不包含请求模型，显示套餐入口 |
| `key_expired` | 401 | key 过期，提示运营方控制台处理 |
| `rate_limited` | 429 | 等待 Retry-After，可重试 |
| `invalid_api_key` | 401 | 缺失、无效、歧义或错误格式的鉴权 |
| `invalid_request_error` | 400 | 原生请求或控制面请求无效 |
| `invalid_previous_response_id` | 400 | 续接绑定未知、跨 key、过期或丢失 |
| `not_found` | 404 | 路径或资源不存在 |
| `method_not_allowed` | 405 | 路径不支持该方法 |
| `request_too_large` | 413 | 请求超过实例公布的限制 |
| `unsupported_media_type` | 415 | 请求正文格式不受该路径支持 |
| `model_not_found` | 404 | 原生请求模型不在可见目录 |
| `unsupported_endpoint` | 400 / 501 | 模型不支持已实现的端点时为 400；实例未实现/声明该端点族时为 501 |
| `stream_unavailable` | 500 | 服务无法提供流式传输 |

这些码是网关错误词表，不取代上游原生错误词表；生产客户端接受未知原生错误并显示 message。业务码对购买行为只提供入口，不能主动发起支付。

OpenAI、Responses、图片、embeddings、rerank 和控制面：

```json
{"error":{"message":"Insufficient balance","type":"invalid_request_error","code":"insufficient_balance","purchase_url":"https://operator.example/purchase"}}
```

Anthropic 保持顶层 `type: "error"`、`error.type` 与 `error.message`，在 error 对象中扩展 `code` 和 `purchase_url`：

```json
{"type":"error","error":{"type":"permission_error","message":"Insufficient balance","code":"insufficient_balance","purchase_url":"https://operator.example/purchase"}}
```

Gemini 保持原生 `error.code` 的整数 HTTP 状态语义和原生 `error.status`；**不能**把业务字符串放进 `error.code`。业务码在原生可扩展 `details` 中使用 `google.rpc.ErrorInfo`：

```json
{"error":{"code":402,"message":"Insufficient balance","status":"PERMISSION_DENIED","details":[{"@type":"type.googleapis.com/google.rpc.ErrorInfo","reason":"INSUFFICIENT_BALANCE","domain":"nomifun-model-gateway","metadata":{"nomifun_code":"insufficient_balance","purchase_url":"https://operator.example/purchase"}}]}}
```

`reason` 是业务码的全大写形式，`domain` 为 `nomifun-model-gateway`，`metadata.nomifun_code` 是小写网关码。没有可用购买链接时，OpenAI / Anthropic 字段为 `null`；Gemini ErrorInfo 的 metadata 原生值必须是字符串，因此省略 `purchase_url`。现有的其他 details 和 native 字段继续保留。

## 8. M0 一致性验收和后续义务

M0 提供 Go Mock、OpenAPI schema 检查和可对独立实现运行的一致性客户端。核心检查包括匿名 meta、三个鉴权头、Gemini 限定查询兼容、错误 envelope、目录任务/首选约束、账户可空整数、原生 JSON 与 SSE、Responses 身份隔离/亲和、Anthropic 会话亲和。Mock 单元测试还验证客户端取消和会话空闲失效。首字节后禁止切换是 M1 原生转发的生产义务：M0 没有真实上游或失败切换实现，不能据此宣称已验收真实失败切换。bundled Mock 使用虚构模型和合成 key，不访问真实模型、账户或支付接口。

独立实现的 conformance 使用自己的测试 key、预期模型/原生请求夹具和声明能力；未声明的可选能力可以明确标记 SKIP，核心端点不得跳过。bundled Mock 的全能力夹具应全部通过且无 SKIP。测试程序只在专门验证两个 Gemini 路径的入站兼容时构造合成查询 key；其他调用不把 key 放进 URL，也不通过命令行参数或日志输出 key。Mock 专用的调试头、固定用量、虚构 response ID、上游通道名和人工错误 key 只属于夹具，不成为桌面或生产协议依赖。

M0 的本地通过表示冻结契约和确定性 Mock 可供客户端开发。它不证明真实上游 SSE/thinking 签名保真、模型工具调用正确、生产持久化恢复、usage 对账、付费账本幂等、支付安全、压力容量或高可用。M1 必须在原生直通实现中验证真实 usage、状态续接和缓存字段；M2 才交付钱包、预扣、结算和支付闭环；M3 交付桌面可选 provider；M4 交付运营与发布审查。不得用参考项目的许可证或代码复用替代这些验证。
