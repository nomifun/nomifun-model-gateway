# 安全边界与本地审查

审查对象为当前 Go 服务、持久化/账务、官方商户适配、控制台及打包配置。源代码和本地验证能
建立具体行为证据，不建立渗透测试认证、真实商户合规、真实上游保真或多节点可靠性结论。

## 已落实的边界

- 用户 API key 和登录 session 使用哈希查询；上游与商户秘密使用 AES-GCM，密文带用途/记录
  身份。主密钥错误拒绝打开现有数据库。API key 明文只在创建时返回，列表和日志不返回它。
- 用户 API key、账户、订单和撤销查询按当前用户筛选，管理员操作另行鉴权。模型目录仅展示
  key 可访问模型；钱包和套餐控制与目录标记分开，included_in_plan 不是权限替代品。
- 金额与用量使用整数，账本与事件身份幂等；未知上游接受状态保留预扣并待对账，不能估计扣费
  或在客户端取消后自动免费释放。人工对账和效果在同一事务中记录管理员审计。
- 支付回调验证签名/加密、商户/应用、订单、金额、币种、交易关联与时间/重放边界；入账与事件
  记录同事务。返回网页和未验证通知不是入账依据。
- 上游/商户 HTTP 不跟随重定向；公开运营/购买链接使用 HTTPS，无凭据。只有管理员可设置
  上游地址，这属于运营方受信任配置，仍需部署时审查 egress/私有网络访问范围。
- 控制台同源请求、session 鉴权、CSP、frame-ancestors none 和 no-referrer；退出撤销服务器会话。
  不把 key 放入 deep link、购买页、URL 或采集日志。Gemini 原生查询兼容例外另见冻结协议。
- 规范化路由/状态日志和指标没有原始路径、查询、headers 或模型内容；GORM SQL 日志关闭。
  运营方代理和监控配置必须保持同样边界。
- 运行镜像非 root、只读根目录、无 shell，固定官方构建/数据库镜像 digest；数据持久化到
  专用目录或数据库。单实例所有权和恢复在启动期协调，PostgreSQL 锁失效由 guardian 触发停止。

## 本次只读审查发现并交给 owner 修正

| 问题 | 所需修正/验证 |
| --- | --- |
| native 输出上限仅预估而未约束实际请求 | 注入/校验协议原生输出上限，计入多候选，捕获上游请求回归 |
| multipart 图像 n 未计入预扣 | 解析/校验并使用实际数量，覆盖余额不足在发送前拒绝 |
| Chat 显式 include_usage=false 可压制终态计量 | 生产计费入口保证 include_usage=true，保留其他未知字段 |
| 控制台退出只清本地 token | 调用服务端 revoke，验证复制的旧 session 不再可用 |
| PostgreSQL 锁连接丢失后进程仍可接单 | guardian 不重连抢锁，停止入口并取消在途上下文；隔离 DB 终止锁会话测试 |
| 缓存/推理高价不能由普通 token 单价上界覆盖 | 预扣采用保守金额上界，实际结算仍按真实分项 usage 精确收费 |
| 仅出现部分 usage 计数却将缺失/null/小数子项视为0完成结算 | 每协议严格要求必需终态字段、整数与分项关系；完整性不足保留有效部分计量并待对账 |

Owner 已增加针对性回归和停止策略；完整的最终镜像/数据库证明见
[实际验收记录](../operations/acceptance.md)。这里只记录审查范围和修正义务，不把未运行的
外部测试写为成功。当前审查未发现已确认的账户/key/订单 IDOR、跨商户错误入账或 webhook 重放
重复入账；这不替代运营环境的持续安全检查。

## 发布前仍由运营方完成

验证 HTTPS、真实上游额度/工具/签名/缓存 usage、真实商户支付通知、备份恢复、日志保留、
取消/对账和与实际硬件匹配的容量。管理账号、主密钥、备份、商户材料与上游授权由运营方保管。
不能把单进程限流、合成负载、可运行镜像或此源代码审查当作 HA / SLA / 商用安全认证。

依赖与来源审查另见 [许可证审计](license-audit.md)。
